# Laboratory Work #3: Synchronization of Threads

## 📝 Описание
Проект реализует задачу синхронизации потоков в рамках одного процесса на языке C++.
Реализована модель взаимодействия **"Главный поток - Рабочие потоки"** (Main-Marker).

**Задача:**
Потоки `Marker` конкурируют за доступ к общему массиву целых чисел.
1. Поток захватывает доступ к массиву.
2. Генерирует случайный индекс.
3. Если ячейка равна `0`, поток помечает её своим `ID`.
4. Если ячейка занята, поток сигнализирует главному потоку о невозможности продолжения.
5. Главный поток (`Main`) управляет жизненным циклом маркеров: останавливает их работу или дает сигнал продолжить.

## 🛠 Технологии
*   **Язык:** C++
*   **API:** Windows API (Threads, Critical Sections, Events)
*   **Стандарт C++:** Использованы элементы C++11 (`<thread>`, `<chrono>`) для управления задержками.
*   **Тесты:** Doctest (Unit-тестирование логики).

## ⚙️ Ключевые особенности
*   **Синхронизация данных:** Использована **Критическая секция (`CRITICAL_SECTION`)** для обеспечения атомарности операций записи в массив.
*   **Управление потоками:** Реализовано через **События (`HANDLE`, CreateEvent)**:
    *   `start_event` — синхронный старт всех потоков.
    *   `cannot_continue_event` — сигнал остановки маркера.
    *   `stop_event` / `continue_event` — управляющие сигналы от Main.
*   **Предотвращение Deadlock:** Реализован механизм освобождения критической секции перед уходом потока в режим ожидания.

## 🧪 Тестирование
Для проверки корректности работы структур данных и логики очистки памяти написаны Unit-тесты с использованием фреймворка **Doctest**.
Тесты проверяют:
*   Инициализацию структур данных.
*   Логику пометки ячеек массива.
*   Логику очистки массива при удалении потока.

## 🚀 Как запустить
1.  Скомпилируйте проект в Visual Studio (или через g++).
2.  Запустите `.exe` файл.
3.  Введите размер массива и количество потоков.

# Laboratory Work #4: Inter-Process Communication (IPC)

## 📝 Описание
Проект реализует задачу синхронизации независимых процессов **Sender** (Производитель) и **Receiver** (Потребитель) через общий бинарный файл.

**Задача:**
*   **Receiver:** Создает бинарный файл, запускает процессы Sender и читает сообщения.
*   **Sender:** Подключается к файлу и записывает сообщения (текст до 20 символов).
*   **IPC:** Обмен данными реализован через кольцевую очередь (Circular Buffer / FIFO) внутри файла.

## 🛠 Технологии
*   **Язык:** C++
*   **API:** Windows API (Processes, Mutex, Semaphore, File Mapping)
*   **Modern C++ Features:**
    *   `<filesystem>` (C++17) — для безопасной проверки и очистки файлов.
    *   `<algorithm>` — использование `std::copy` вместо C-style копирования.
    *   `<chrono>` — логирование времени получения сообщений.
*   **Тесты:** Catch2 v2 (Unit-тестирование математики очереди).

## ⚙️ Архитектура и Синхронизация
Для синхронизации доступа к файлу между процессами используются именованные объекты ядра:
1.  **Mutex (`Lab4_FileMutex`):** Обеспечивает взаимное исключение при записи/чтении файла (защита от Race Condition).
2.  **Semaphore (`Lab4_SemFree`):** Контролирует количество свободных мест в очереди (блокирует Sender, если очередь полна).
3.  **Semaphore (`Lab4_SemUsed`):** Контролирует количество сообщений (блокирует Receiver, если очередь пуста).

## 🧪 Тестирование
Написаны Unit-тесты с использованием фреймворка **Catch2**.
Проверяется критически важная логика работы с бинарным файлом:
*   Валидация размеров структур (`sizeof`) для гарантии бинарной совместимости.
*   Корректность адресной арифметики (расчет смещений `getOffset`).
*   Математика кольцевого буфера (циклический сдвиг индексов).

## 🚀 Как запустить
1.  Скомпилируйте проекты `Receiver` и `Sender`.
2.  Убедитесь, что `Receiver.exe` и `Sender.exe` находятся в **одной папке**.
3.  Запустите **только** `Receiver.exe`.
4.  Следуйте инструкциям в консоли (введите имя файла и количество процессов Sender).
